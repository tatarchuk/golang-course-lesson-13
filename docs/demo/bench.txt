--- comparison with the README numbers (section 5 of the demo README) ---
# Measured value                      README (Linux, 1 vCPU, Go 1.22, 3 s)   this Mac (M2 Pro, Go 1.27.1, 2 s)
# Copy on the wire                    Protobuf 28 B, JSON 85 B (~3x)         Protobuf 28 B, JSON 85 B (3.0x): identical, a property of the format
# Serialize + deserialize             Protobuf ~410 ns, JSON ~1850 ns (4.5x) Protobuf 215.6 ns, JSON 637.7 ns (3.0x)
# One call, native gRPC               ~33 us                                 60.7 us (188 allocs/op)
# One call, hand-written REST/JSON    ~24 us                                 49.5 us (71 allocs/op)
# One call, REST through the gateway  ~80 us                                 125.9 us (338 allocs/op)
# Parallel calls (not in the README)  -                                      gRPC 16.1 us/op, REST 15.4 us/op (10 cores)
#
# What we saw, as the README asks to report: the ordering is the same as in the README. Protobuf is 3x smaller and
# about 3x faster to serialize; for one tiny request on loopback the hand-written REST path is still the fastest
# and the gateway path the slowest (two protocol hops), i.e. the transport overhead dominates (slide 10). The absolute
# per-call numbers are higher on this macOS machine than in the README's Linux run (different network stack and
# scheduler, 2 s runs); the parallel benchmarks show both protocols at about 16 us per call on 10 cores.
